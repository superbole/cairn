## What changed and why

`hooks/repo_sweep.py`'s `summary_line()` used to print the cross-repo staleness banner straight
from the last detached refresh's JSON cache, with no re-check. Two real incidents showed that cache
can be flatly wrong by the time it is read: 2026-09-24 it named `agent-reentry` as "5 behind" after
the directory had been deleted from `~/Projects` entirely; 2026-09-25 it named a deleted repo *and*
two siblings that were actually fully in sync (a live fetch + `rev-list` showed 0/0 for both, one of
them pushed from that machine an hour earlier). `Path.exists()` alone was not enough to catch the
second case.

Fix, entirely inside `summary_line()` plus two small new helpers — no other file in the lane's
scope needed to change:

- **`_local_behind(repo)`** (new) — the same "how many commits behind" question as the existing
  `_behind()`, but answered from refs already on disk: `git rev-list --count HEAD..@{u}`, no
  `git fetch`. Returns `None` for anything it can't answer (no upstream, detached HEAD, git
  missing, the repo not existing, or the short timeout tripping), never `0` for those cases.
- **`_cache_age_text(at)`** (new) — `"as of HH:MM"` for a valid `at` timestamp, else the generic
  `"from last session"` — never a fabricated clock time from a missing/malformed `at`.
- **`summary_line()`** now, for at most `MAX_NAMED` named repos (the ones it is about to print,
  never the collapsed tail): does one `Path.exists()` — drop if the directory is gone — and, if it
  exists, one `_local_behind()` call.
  - `None` (can't verify) → **keep the cached count**. Dropping here would silently hide a
    genuinely-behind repo over one flaky `git` call — the same class of bug this fix exists to
    remove, one level up.
  - `0` → the repo has caught up since the cache was written → **drop it**.
  - `>0` → print the **fresh** count, not the stale cached one.
  - The line now also carries the cache's age (`"as of 14:02"` / `"from last session"`), read from
    the `at` field the cache already writes.
- Added `LOCAL_CHECK_TIMEOUT = 2` (seconds) — bounds the new per-repo local `git` call. Worst case
  at most `MAX_NAMED` (5) of these run in the foreground at session start; each is local-only (no
  network), so this is a lock-contention/hung-git guard, not a network timeout. The no-network
  contract for session start still holds — `refresh()`/`spawn_refresh()`/the detached child are
  untouched, `_behind()` (which does fetch) is untouched, and nothing calls `git fetch` from
  `summary_line()`.
- Rejected explicitly (per the brief): refreshing inline at session start — the hook must not do
  network I/O, and this fix does not add any.

`tools/test_repo_sweep.py`: added `import time`; extended the module docstring's failure-mode list
with the B58 case; added four new fixture cases inside the existing refresh/summary_line block
(cached repo whose directory is gone → silence; cached repo whose real, already-fetched
remote-tracking ref now reads 0 → dropped, not repeated stale; cached repo with no upstream at all
→ recheck fails, cached count is kept; malformed `at` → `"from last session"`, not a fabricated
time) plus one age-text check on the happy path. The pre-existing MAX_NAMED-truncation case now
also exercises the "can't verify" path for real: it creates plain (non-git) directories `r0..r7`
under the fixture's `Projects/` so each named entry survives the `Path.exists()` check but fails
the `git rev-list` recheck (no `.git` there at all), so it keeps its cached count — preserving the
original assertion that the **true total** (8) still appears on the line, now for the right reason.

## Decided on Sheldon's behalf

1. **On a recheck failure, keep the cached count rather than dropping the repo or printing 0.**
   The brief flagged this explicitly ("a re-count failure must not silently hide a
   genuinely-behind repo"). `_local_behind` returns `None` for no-upstream, detached HEAD, git
   missing, or the timeout, and `summary_line` treats all of those the same: reprint what the last
   real (fetching) sweep found, rather than either guessing 0 or going silent.
2. **`LOCAL_CHECK_TIMEOUT = 2` seconds.** The brief asked for "a short timeout"; a local
   `rev-list` against an already-populated remote-tracking ref is normally sub-10ms, so 2s is
   generous headroom for lock contention without letting a hung `git` compound across up to
   `MAX_NAMED` (5) sequential calls into a noticeable session-start stall (worst case 10s, versus
   the multi-second-per-repo cost the module docstring already accepts for the fetching sweep).
3. **Age text is two-valued, not a numeric "Nm ago" style.** Matched the brief's own two examples
   (`as of 14:02` / `from last session`) rather than inventing a third form (e.g. relative age in
   minutes), since the brief was explicit that a malformed/missing `at` must not be dressed up as
   a specific time — a plain fallback string is the simplest way to guarantee that.
   `time.localtime` (machine-local time) is used, matching every other `%H:%M`/`%Y-%m-%d` timestamp
   already in this plugin (`wrap_receipt.py`, `session_orientation.py`, `scheduled_task_watch.py`).
4. **When the recheck drops a repo from the shown names, the collapsed tail count (`extra`) is
   left as originally cached** — i.e. no work is spent re-verifying or backfilling replacements for
   names beyond the first `MAX_NAMED`. This keeps the "at most `MAX_NAMED` local git subprocesses"
   bound literal, at the cost that a repo past the naming window could itself be equally stale;
   that risk already existed before this fix (the `"… N more"` tail was never verified) and B58's
   brief scoped the fix to "the named repos it is about to print", not the whole cache.
5. **Existing `test_repo_sweep.py` fixtures for the MAX_NAMED-truncation case were adapted** (real
   plain directories `r0..r7` added under the fixture's `Projects/`) rather than left as
   directory-less names, because with the B58 fix a directory-less cached name is now (correctly)
   dropped as "gone" — the old assertion ("the true total still appears") would otherwise have
   started failing for a reason unrelated to what that test was written to check. Chose "existing
   non-git directory" (so the recheck itself fails and the cached value is kept) over "existing
   real git repo genuinely behind" to keep the fixture cheap and to also exercise the "can't
   verify, don't drop" path inside the same assertion.
