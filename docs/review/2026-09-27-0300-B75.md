# B75: `run_tests.py`'s leak detector blames a test for a concurrent session's own state dir

Lane afk-03, branch `afk/2026-09-27-03-B75-leak-attribution`. Model Sonnet, effort medium, AFK.

## What changed and why

`plugins/cairn/tools/run_tests.py`'s B74 leak detector snapshots `~/.claude/reentry-state/`
before and after every test file and blames whichever file was running for any new directory
that appears. That plain diff cannot tell "this test wrote here" apart from "an unrelated
concurrent Claude Code session's own `SessionStart`/`Stop` hook wrote its own state dir here
while this test file happened to be running" — reproduced twice against the real suite (an
`agent-<id>-<hash>` dir from an unrelated agent-worktree session, 2026-09-26; an empty
`afk-02-<hash>` dir from a sibling worktree lane, 2026-09-27), both times failing an otherwise
fully passing run.

Ruled out per the brief: relaxing the detector to warn instead of fail (the B74 docstring already
explains why a real leak must fail the run), and dropping the global diff for a per-file
`CLAUDE_CONFIG_DIR` (that would silently sandbox a test that forgot to override it itself,
hiding the exact bug B74 exists to catch — reintroducing the bug one level up, just moved from
"false failure" to "false pass").

Instead, every newly-appeared directory NAME is attributed before it is allowed to fail anything
(`_classify_new_entries` in `run_tests.py`):

1. **Ignored** if its slug matches a REAL, currently-existing project or worktree. Candidates
   come from two read-only, no-side-effect sources gathered once per run
   (`_real_roots`/`_git_worktree_roots`/`_recorded_project_roots`):
   - `git worktree list --porcelain` (every live lane of this repo, including main) — this is
     exactly the `afk-02` reproduction;
   - `root` fields from every OTHER `last_exit.json` already sitting in the real state dir (the
     same source `check_repos.py`'s `known_roots()` reads) — covers a concurrent session in a
     completely different repo, which the `agent-<id>-<hash>` reproduction looks like.
   A candidate only counts if it still exists on disk (`root.is_dir()`), so a stale record for a
   deleted worktree can never falsely clear a real leak.
2. **Blamed** (still fails the run) if its slug instead matches a directory THIS test's own run
   just created under the system temp dir (`_snapshot_temp_dir()` before/after, same shallow
   shape as the state-dir snapshot) — the exact shape of a fixture that forgot to override
   `CLAUDE_CONFIG_DIR`, i.e. a genuine B74 leak.
3. **Blamed** (still fails the run) if it matches NEITHER list. An unrecognised new name is not
   proof of innocence; treating it as harmless by default would reintroduce the exact blindness
   the detector exists to prevent.

`_slug_for` duplicates `reentry_state.state_dir`'s slug math (sanitised name + 10 hex chars of a
SHA-1 of the lowercased resolved path) rather than importing/calling it, for two reasons: calling
the real `state_dir()` against every candidate path would itself `mkdir` a real state directory
for each one as a side effect, and this file must keep working even if `hooks/reentry_state.py`
is mid-edit in a sibling lane (same reasoning the file's existing `_real_state_base()` already
gives for duplicating instead of importing).

**Round 2 (same day): a candidate list computed once at suite start missed a worktree ADDED
mid-run.** The orchestrator's own full run reported `test_check_credentials.py` for two
"unrecognised" leaks, `afk-05-<hash>` and `afk-06-<hash>` — both were live worktrees
(`.claude/worktrees/afk-05`, `afk-06`), but they did not exist yet when `_real_roots` ran once at
the top of `main()`, because `git worktree add` for both ran WHILE the suite was already in
progress. The cached candidate list could never have matched a worktree that did not exist when
it was built — this is the exact concurrent-lane shape the whole fix exists for, just for a
worktree whose birth, not just its hook firing, happened mid-run.

Fix: `_classify_with_refresh` wraps `_classify_new_entries`. It tries the cached `real_roots`
first; if anything is still blamed after that, it recomputes `_real_roots` fresh — exactly once
— and re-classifies against the fresh list before accepting the blame, then hands the fresh list
back to the caller (`main()`) to use as the cache for every test file after this one. The normal
path (nothing blamed) never pays for a recompute at all, so this does not turn every test file
into a `git worktree list` call. Also fixed while in there: the leak-summary sentence read "keys
to neither a real, existing project/worktree, nor an unrecognised name attributed away", which
said nothing coherent — reworded to state plainly that each row's reason (temp-fixture match vs.
unrecognised) is printed above it.

Files touched:
- `plugins/cairn/tools/run_tests.py` — the fix (docstring sections added for B75 and B75 round 2;
  `_slug_for`, `_git_worktree_roots`, `_recorded_project_roots`, `_real_roots`,
  `_snapshot_temp_dir`, `_classify_new_entries`, `_classify_with_refresh` added; `main()` wired to
  classify-with-refresh before blaming, and to report ignored attributions separately from real
  leaks; the garbled summary sentence reworded).
- `plugins/cairn/tools/test_run_tests.py` — new, unit-tests the classifier and the refresh
  behaviour directly.

## Decided on Sheldon's behalf

- **Candidate sources for "real, existing project/worktree" are `git worktree list` plus
  `last_exit.json` `root` fields already in the real state dir — nothing wider.** Considered also
  walking `~/Projects` or similar, but that hard-codes a machine-specific layout into a file that
  runs on every machine that installs this plugin, and the two sources chosen already cover both
  reproduced cases exactly. If a third false-positive shape shows up that neither source catches,
  it is a `BACKLOG.md` candidate, not a reason to have widened this speculatively.
- **A name matching neither the real-root list nor this run's own temp dirs is still blamed, not
  reported as a third "unknown" bucket that skips failing the run.** The brief explicitly asked
  this question ("does this reintroduce its own bug one level up?"); the answer here is fail
  closed — an unattributed new directory gets a distinct reason string (`"unrecognised"`) in the
  printed leak table so a human can tell it apart from a confirmed-fixture leak, but it still
  counts toward the exit code, because the alternative (silently passing) is the exact blindness
  B74 was written to prevent.
- **Reimplemented `_slug_for`, and the `last_exit.json`-reading helper, rather than importing
  `reentry_state` or `check_repos`.** This runner's own docstring already commits to never
  crashing because a sibling file is half-written mid-edit by another lane; importing either
  module would break that guarantee. The duplication is the same shape as the file's existing
  `_real_state_base()`, which documents the identical tradeoff.
- **Left the two genuinely leftover `reentry-state/agent-<id>-<hash>` (and similar) directories
  from past sessions alone.** Nothing in this fix deletes or touches existing real state-dir
  entries; B75's second half ("nothing cleans them up") is a separate sweep, not this ticket's
  detector fix, and is listed below rather than attempted here.

## Chose not to do

- **Did not touch any hook under `plugins/cairn/hooks/`.** Out of scope for this lane by the
  brief's hard rule. Two follow-ups the brief asked to be recorded as recommendations rather than
  code:
  - Whether `session_orientation.py` (or whichever hook stamps state on `SessionStart`) should
    skip stamping for a `cwd` under `.claude/worktrees/*` — recommendation: probably not skip
    unconditionally (a worktree lane is a real, distinct project identity and its own dirty/wrap
    history is legitimately worth tracking under its own slug), but it would be worth teaching
    `check_exits.py`/`check_repos.py` to fold a worktree's records under its parent repo's
    identity for reporting, since right now every lane accumulates its own permanent entry.
  - Whether a sweep should prune `reentry-state/*` directories whose recorded/derivable project
    path no longer exists on disk — recommendation: yes, this is worth building (a `check_repos.py`-
    adjacent `prune_state.py` that removes a slug directory once neither a `last_exit.json` root
    nor any live worktree/`git worktree list` entry resolves to it, dry-run by default given it's
    a delete). Not built here: it is a distinct tool with its own review, not part of attributing
    a leak inside the test runner, and deleting real (if stale) operator state from an AFK lane
    without review is exactly the kind of one-way action this session should not take unattended.
- **Did not add a third "unknown, don't fail" bucket** — see "Decided on Sheldon's behalf" above.
- **Did not chase down what specifically wrote the `agent-<id>-<hash>` and `afk-02-<hash>`
  directories still sitting in the real state dir from the original two reproductions** (if they
  are in fact still there) — that is exactly the stale-directory sweep described two bullets up,
  and is a separate, reviewable change.

**For the attended session that picks this up:** this lane only committed nothing and pushed
nothing (per the hard rules for this run) — the working tree here has the two files above
modified/added but uncommitted. Before this can be called done: review the diff, commit, update
`CHANGELOG.md`, close B75 in the backlog/issue host, and decide whether a version bump is
warranted (this is a bugfix to a dev-only test tool, not a user-facing behavior change, so a patch
bump would be the default reading, but that call belongs to whoever runs `/cairn:wrap` here).

**A blind spot remains, for the reviewer to accept or reject.** A test that forgets `CLAUDE_CONFIG_DIR` and uses the checkout the suite runs in as its project would write that checkout's own slug. The same live-hook-versus-test ambiguity makes it hard to close without a per-file sandbox (rejected in the dossier). An option: never ignore the slug of `ROOT` itself, which would keep tonight's `afk-02` shape (orchestrator cwd = suite worktree) as a failure.
