# B76: model labels name the family, not a version (AFK lane 01, 2026-09-27 03:00)

Branch `afk/2026-09-27-01-B76-model-labels-family`, worktree `afk-01`. Nothing committed, nothing
pushed.

## What changed and why

**Option (a), as the brief recommends.** A label is the family (`Opus`, `Sonnet`, `Haiku`, `Fable`).
A version after it (`Opus 5.5`, `Fable 5.1`) is optional. Existing `Opus 5` / `Sonnet 5` /
`Haiku 4.5` labels still parse, and none of the existing `NEXT.md` or `BACKLOG.md` files were
touched.

**The defect was worse than "reads as missing".** `backlog_file.render()` rebuilds every fields
line from the parse (`fields_line(it)` uses `it["model"]`). So an item labelled `` `Opus 5.5` ``
parsed as `model=None`, and the next `write()` (every wrap's `sync_backlog`) **deleted the label
from the file**. The new test 15 in `test_backlog_file.py` shows this: run against the pre-B76
`backlog_file.py`, it fails 6 checks, including `write() keeps every family/version label` →
`got={1: None, 2: None, 3: None, ...}`. It passes on the new code.

Files:

- `plugins/cairn/hooks/backlog_file.py`: the new `_MODEL_LABEL = r"(?:Opus|Sonnet|Haiku|Fable)(?:\s+\d+(?:\.\d+)?)?"`
  holds the family list and the version shape in one place. `_MODEL_RE` wraps it in the
  backticks it already required. Group 1 is the whole label as written, so the round-trip stays
  byte-for-byte. The closing backtick is what refuses `Opus 5.5.5` and `Opus5`.
- `plugins/cairn/tools/validate_next.py`: `_MODEL_RE` used to be built by stripping the backticks
  out of `bf._MODEL_RE.pattern`.
  - **The one-level-up bug.** With the backticks optional and a bare family word now a valid label,
    that approach would accept `Opus 5.5.5` (truncated to `Opus 5.5`). It would also count a title
    like "Ask about Opus pricing" as having a model.
  - **The fix.** The pattern is now built from `bf._MODEL_LABEL` and anchored as a field, the same
    way `_EFFORT_RE` already is: `\b` before it, and only `·`, `—` or end of line after it.
  - **Real files still pass.** Checked against this repo's `NEXT.md` (3 queue items, 6 watches, OK).
    A read-only parse of the repo's real `BACKLOG.md` with the old and the new module gives 70
    items, 69 with a model under both, and zero differences.
- `plugins/cairn/rules/CLAUDE.md`:
  - The queue and watch templates now write `Opus`.
  - The Model tiering bullet gains 5 lines. The field names the family, you compare families and
    never versions, the order is **Haiku < Sonnet < Opus < Fable**, and `Fable` is written only
    when the brief says why Opus is not enough.
- `plugins/cairn/skills/next/SKILL.md`:
  - The examples use the family.
  - The mismatch paragraph now states the scale. `Opus 5` on an `Opus 5.5` item is the same tier,
    Fable on an `Opus` item is above, and Opus on a `Fable` item is below, so it stops.
- `plugins/cairn/skills/wrap/SKILL.md`: the examples use the family, plus one sentence saying the
  model is the family, never a release number.
- `plugins/cairn/cursor/preamble.md`: the substitution row now reads `` model tier (`Opus`, `Sonnet`) | pick the current model of that family ``.
- `plugins/cairn/cursor/rules/cairn.mdc`: regenerated by `tools/build_cursor.py`, which is its
  documented generator. It is not hand-edited. `--check` reports `cursor artefacts: current`.
  `.cursor-plugin/plugin.json` was rewritten with identical bytes and shows no diff.
- `plugins/cairn/tools/test_backlog_file.py` §15 and `test_validate_next.py` §21 are the new tests
  (details under Verification).

None of the hook files owned by the other session were touched. `session_orientation.py` and
`item_open.py` contain `Opus 5` only in comments that describe the shape. They have no model
regex of their own, so they needed no change.

## Decided on Sheldon's behalf

1. **Option (a), not (b).** Labels name the family. Versions are optional, accepted, and never
   compared.
2. **The tier order is Haiku < Sonnet < Opus < Fable.** Fable sits **above** Opus.
   - **Evidence.** None of it is on disk in this repo: `grep -rni fable` finds only B76 itself. It
     comes from the bundled `claude-api` skill's model table (cached 2026-06-24):
     - Claude Fable 5.1 is described as "Anthropic's most capable widely released model".
     - Its price is $10 / $50 per MTok, against $4 / $20 for Opus 5.5, so about 2.5×.
     - Opus 5 is $5 / $25, Sonnet 5 is $2 / $10, and Haiku 4.5 is $1 / $5.
     - The Agent tool lists `fable` as a model option alongside opus, sonnet and haiku.
   - **Assumption.** Price and "most capable" are taken as a proxy for "the stronger model for
     judgement". No measurement of Fable against Opus on this portfolio's work exists.
3. **Fable is not the default for judgement work.** `Opus` stays the label for diagnosis and
   design. `Fable` is written only when the brief says why Opus is not enough. This is the same
   "don't pay for a tier the item doesn't need" logic his 2026-09-27 over-tier rule already applies.
4. **What that means for the mismatch check.** It follows from (2) and the existing asymmetric rule:
   - Fable running an `Opus` item is ABOVE, so name the cheaper tier and wait, unless the item is small.
   - Opus running a `Fable` item is BELOW, so it is a HARD STOP.
   - `Opus 5` running an `Opus 5.5` item is the same tier.
5. **The tier order stays prose, not code.** No code performs a mismatch check today: it is the
   agent reading `skills/next/SKILL.md`. Adding a `MODEL_TIERS` constant with no caller would be
   dead code, so I didn't.
6. **Where the field anchor is too loose.** The field anchor in `validate_next.py` still accepts a
   family word that ends an **un-bolded** title right before `—` (`1. Upgrade to Opus — high ·
   AFK/Auto`). Every template bolds the title, and the pre-B76 regex had the same exposure for
   `Opus 5`, so I accepted it rather than add a title parser.

**Proposed `docs/decisions.md` row** (for the attended session to add verbatim, next free `D` id):

| D? | What does a model label name, and how are tiers compared? | 2026-09-27 | **The family, with an optional version** (`Opus`, `Opus 5.5`). `backlog_file._MODEL_LABEL` is the single pattern, `(?:Opus\|Sonnet\|Haiku\|Fable)(?:\s+\d+(?:\.\d+)?)?`; `validate_next` builds its copy from it, anchored as a field. The mismatch check compares families by the order **Haiku < Sonnet < Opus < Fable**, never by version. Fable ranks above Opus because the claude-api model table calls it the most capable widely released model at ~2.5× Opus 5.5's price. It is written only when a brief says why Opus is not enough. Decided unattended by the B76 lane, on Sheldon's behalf. | **(b) keep versions and widen the regex only.** Smaller diff, but a queued brief outlives releases, so the label goes stale while the item waits.
