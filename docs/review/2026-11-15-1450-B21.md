# B21 dossier: the dangling-pointer warning classifies by the id's position on the line

Branch `afk/2026-11-15-03-B21-pointer-shape`. Unattended lane. Nothing merged.

## 1. What changed and why

`orphaned_pointers_report()` (`plugins/cairn/tools/sync_backlog.py`) warned about every line
naming an id the sync is about to drop. Path exclusions and the closing-word filter left it at
precision 0: what remained was historical citation. The fix tests the id's syntactic position.

New helper `_is_pointer_line(ln, n, in_queue)`. A line counts only when the id is in one of:

- a markdown link (in the link text or the target);
- a `blocked by` field (id directly after it, alone or in a comma / `and` / `+` list of ids);
- an arrow, `→ Bn`, `→ path Bn` or `-> Bn`;
- a numbered list line inside NEXT.md's `## Queue` section (section tracked per file).

Everything else (`Related:`, `see`, `same as`, `family as`, parentheses, plain sentences) is a
citation and is not reported. The path exclusions and the closing-token filter stay as the
second guard. No file was edited to remove citations. The v1.69.0 root-refusal logic is untouched.

Tests (`plugins/cairn/tools/test_sync_flags.py`): new section 19 covers 7 pointer shapes
(reported), 7 citation shapes including a longer id `B460` (not reported), and Queue-section
vs other-section numbered lines. Five older fixtures used bare prose ("still tracking B46",
"still waiting on B46", README "B87 is still open work", "see B87 for the design", a design
doc's subject line) as the example of a live pointer. That is exactly the shape B21 declares a
citation, so those fixtures were changed to structured shapes (`blocked by B46`) or their
expectation flipped to "not reported". Section 13's count went from 5 hits to 2.

## 3. Decided on the owner's behalf

- Link shape fires whenever the id is in a link's text or target, even in a sentence
  (`see [B46](...)`). A link is structured; a wrong hit costs one line, a missed pointer costs
  a confused re-entry.
- The Queue rule applies to NEXT.md only, and any numbered line there counts, even one that
  names the id as a citation.
- `blocked by` also accepts a list (`blocked by W1, B46`) and backticked ids.
- Changed five existing test fixtures that encoded the old prose-as-pointer behaviour.

## 4. What I chose not to do

- Not matched, by the spec's own shape list: `Blocked on Bn` (e.g. BACKLOG.md line 246 reads
  "Blocked on B23 for the real ...") and brief provenance lines like "from `BACKLOG.md` B61".
  Both can be genuine pointers to a closed item. Adding them is a one-line regex each, but the
  entry names the shapes and I did not widen it unattended. Worth a follow-up decision.
- Did not add shapes for `## Decisions` / `## Watching` list lines: the arrow form in D lines
  already matches and W lines carry no id pointers in practice.
- Did not delete or reword any citation anywhere, did not touch BACKLOG.md, NEXT.md,
  CHANGELOG.md, any plugin.json, or the v1.69.0 root logic. No version bump (owner's call).
