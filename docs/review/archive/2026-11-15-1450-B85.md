# B85: check_repos.py reports pushed afk/ branches as unpushed

## What changed and why
- `plugins/cairn/tools/check_repos.py`: `_unpushed` now, for a branch named `afk/...`, compares HEAD with
  `origin/<same branch>` instead of `@{upstream}`. If `origin/<branch>` does not exist it returns no count
  and the note "afk branch has no origin/<branch> (never pushed, or deleted after merge)", so the repo shows
  `[!!]` with an honest reason rather than a false "1 unpushed". Other branches are unchanged.
- `docs/running-a-batch.md`: the lane-branch creation line is now `git switch --no-track -c afk/... origin/main`,
  with the reason, so new lanes no longer track `origin/main`.
- `plugins/cairn/tools/test_check_repos.py` (new): builds a throwaway repo with a local bare origin, creates an
  afk branch that tracks origin/main (the B85 shape), and checks: never pushed gives a note; pushed gives 0;
  one more commit gives 1; `main` still uses its upstream. Before the fix the "pushed" case would count the
  lane's own commit against origin/main (1, not 0); I did not run it against the old code.
