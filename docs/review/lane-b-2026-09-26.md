## What changed and why

- **`plugins/cairn/hooks/run.sh`** — two changes, both backward-compatible with
  `sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" <hook>.py [args]`:
  1. **It also runs `tools/` files.** A bare name is still `hooks/<name>`; a name with a slash must
     start `hooks/` or `tools/` and contain no `..`, anything else is refused on stderr with exit 0
     (same "never block" rule as the missing-interpreter path). One launcher, one interpreter
     resolution order. No second shim.
  2. **Root resolution.** `CLAUDE_PLUGIN_ROOT` is used only when `$0` is literally
     `"$CLAUDE_PLUGIN_ROOT/hooks/run.sh"` — true of every hooks.json command, so the hook path is
     byte-for-byte what it was (no fork added on PostToolUse). Otherwise the root is run.sh's own
     directory's parent, computed with parameter expansion + `cd`/`pwd` builtins instead of
     `dirname` (the old fallback called `dirname`, an external, which failed on a PATH holding
     only the interpreter — the test caught this). Handles `/`, all-backslash Windows paths, and a
     bare `run.sh`. This means a checkout run by path never silently runs the installed copy
     because some env var pointed there.
  Missing-Python message now says "no cairn hook or tool" instead of "none of the cairn hooks".
- **`plugins/cairn/skills/wrap/SKILL.md`** — all 14 `python "$CLAUDE_PLUGIN_ROOT/…"` call sites
  rewritten to `sh "<root>/hooks/run.sh" <hook>.py …` / `… tools/<tool>.py …`. Plus two call sites
  the brief's grep missed: step 5b's `python plugins/cairn/hooks/push_check.py --since …` (bare
  python AND a path relative to the cairn repo, so wrong in every other project) and the
  "Run `hooks/wrap_receipt.py --check`" in the verdict rule. One sentence defining `<root>` added
  at the top of `## Procedure`. The measure_context line that previously ended `<root>` (meaning
  the PROJECT root) became `<project-root>` so the placeholder has one meaning.
- **`plugins/cairn/skills/next/SKILL.md`** — 2 call sites rewritten; the same `<root>` sentence
  after the "No `NEXT.md` here?" paragraph.
- **`plugins/cairn/rules/CLAUDE.md`** — the 2 `wrap_receipt.py` lines rewritten; one 3-line note
  defining `<root>`: two directories above a cairn skill's base directory, **or** cairn's
  `installPath` in `~/.claude/plugins/installed_plugins.json` (the rules file is loaded with no
  skill, so it needs a second source of the root). The duplication with the skills is deliberate
  and was not deduped.
- **`plugins/cairn/tools/test_hook_launcher.py`** — the fixture now launches a COPY of run.sh
  inside the fake root by the exact string CLAUDE_PLUGIN_ROOT names (the real hooks.json shape),
  and strips any inherited CLAUDE_PLUGIN_ROOT. New section 4 (agent's form): unset root → own
  plugin; a root naming another plugin loses; `tools/x.py` and `hooks/x.py`; four refused

- **`plugins/cairn/tools/test_skill_calls.py`** (new) — the pin. Over `skills/*/SKILL.md` and

  `python.exe` before a `.py`; no `$CLAUDE_PLUGIN_ROOT/` or `${CLAUDE_PLUGIN_ROOT}/` as a path;
  a self-test that the patterns catch each variant; every `run.sh` call spells the root `<root>`,

## Decided on Sheldon's behalf

- **Root via the skill's base directory, not an env var.** A literal `<root>` placeholder, defined
  in words, fails loudly (`sh: <root>/hooks/run.sh: No such file`) if an agent pastes it — unlike
  `$CLAUDE_PLUGIN_ROOT`, which silently became `/hooks/…`.
- **`run.sh` takes `tools/…`, rather than a second shim.** A second shim would duplicate the
  interpreter order D31 chose and could drift from it.
- **`run.sh` prefers its own location** unless `$0` is exactly the `CLAUDE_PLUGIN_ROOT` path.
- **Two extra call sites fixed** (push_check, the verdict-rule `--check`) outside the brief's 17,
  as the same defect.
- **Proposed `docs/decisions.md` row — a NEW row (D32 or next free), not an edit to D31.** D31
  answers "how does a HOOK find Python"; this answers "how does the AGENT find the plugin", which
  is a different question with a different rejected set. D31's text "run.sh should only launch
  files under hooks/" is widened by this row; the row says so.

  > | D32 | How does the agent's own shell find a cairn script when `$CLAUDE_PLUGIN_ROOT` is unset there and `python` may not exist? | 2026-09-26 | **Every skill and rules command goes through `hooks/run.sh`, written `sh "<root>/hooks/run.sh" <hook>.py` or `… tools/<tool>.py`, with `<root>` defined in one sentence per file as two directories above the skill's base directory** (the one path the harness always prints), and in `rules/CLAUDE.md` alternatively cairn's `installPath` in `~/.claude/plugins/installed_plugins.json`. `run.sh` now accepts `hooks/` or `tools/` relative names (no `..`), and trusts `CLAUDE_PLUGIN_ROOT` only when it names run.sh's own plugin. Pinned by `tools/test_skill_calls.py`. Widens D31's "run.sh only launches hooks/". B59. | **A `CAIRN_PLUGIN_ROOT` export written into `settings.json` `env` by `install_rules`**: a settings write every update (D9 disclosure), stale on every version bump until the next SessionStart, and another lane owns install_rules. **Keep `python`, fix only the root**: stock Ubuntu still fails at the verdict step, the aim line. **One prose line "python means python3"** (B59 option b): prose is what agents reason past, and it fixes nothing on the root. **A second shim under `tools/`**: duplicates D31's interpreter order, two things to keep in step. **A glob of `~/.claude/plugins/cache/*/cairn/*/`**: six versions sit there on one machine here, so it resolves to the wrong one. **Printing the root from the SessionStart hook**: breaks the total-silence rule for projects without `NEXT.md`. **Cost accepted:** +189 bytes (~47 tokens) of always-loaded rules text; the lines are longer; native Windows without Git for Windows has no `sh` (already B60). |
