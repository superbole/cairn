## What changed and why

**`plugins/cairn/hooks/archive_guard.py` (new).** A PreToolUse hook for
`mcp__ccd_session_mgmt__archive_session`. It imports `wrap_receipt` and computes
`baseline()` → `attribution()` → `steps()` → `verdict()` exactly as `--check` does. It does not
parse `--check`'s output.
- `OPEN`: deny with exit 2. Stderr names each OPEN root, its `! reason` lines, the wrap command
  (via `reentry_state.wrap_command`, so a project-local `/wrap` wins), and that commits made after a
  wrap are not covered. It also names the sidebar as the user's escape hatch.
- `SET` / `NOT DUE`: exit 0, no output.
- `UNKNOWN`: exit 0 plus one-line JSON `{"systemMessage": ...}` naming `CAIRN UNKNOWN`.
- Any of these also allow, silently: another session's id, no `session_id` in `tool_input`, a tool
  other than archive, a root with no `NEXT.md`, an unparseable or non-object payload, and any
  exception (`decide()` wraps everything, and `main` has an outer `except`).
- "Self" means `tool_input.session_id == "self"`, or the caller's own id from the payload's
  `session_id` spelled out. Without the second form the guard would only be testing the spelling.
- The baseline session comes from the payload's `session_id`, falling back to
  `CLAUDE_CODE_SESSION_ID`. It is sanitised the same way `wrap_receipt.session_id()` does it.
- **Roots judged:** `project_root()`, the git toplevel of the payload `cwd` (a session that has
  `cd`-ed into another repo), and, when `project_root()` has no `NEXT.md`, its opted-in children
  (the B2 parent-directory session). A root is only judged if it has a `NEXT.md` AND a baseline
  for THIS session. If any judged root reads `OPEN`, the archive is denied.
- **Output is written as UTF-8 bytes, and a failed write cannot change the decision.** This was
  found in verification. The reasons carry em-dashes and Windows stderr is cp1252. If an encode
  error had reached the outer `except`, it would have turned a deny into a silent allow. A test
  now pins this.

**`plugins/cairn/hooks/hooks.json`.** One new object in `PreToolUse`: matcher
`mcp__ccd_session_mgmt__archive_session`, command
`sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" archive_guard.py`, timeout 20. That is the same shape and
timeout as `staged_review_guard.py`, and `test_hook_launcher.py`'s shape check passes.

**`plugins/cairn/tools/test_archive_guard.py` (new).** Fixture repos under `mkdtemp` only, with a
temp `CLAUDE_CONFIG_DIR`, a fake session id, and `CLAUDE_PROJECT_DIR` set per subprocess. It runs
the hook as a subprocess with JSON on stdin, and once through `run.sh` to prove exit 2 passes
through. It covers every case in the spec plus: own id spelled out, NOT DUE, no target, other tool,
no-NEXT.md project, a `cd` into an OPEN repo, a parent-dir session with an OPEN child, an
ASCII-only stderr, and `verdict()` raising.

**`plugins/cairn/hooks/wrap_receipt.py`: not edited.** For the spec's "Also check", `--check`'s
`verdict()` already reads OPEN when HEAD moves after a SET receipt. The `marker` step compares
`.claude/.last_wrap` to HEAD, so a post-wrap commit makes it `skipped: .last_wrap is X, HEAD is Y`,
which gives OPEN. Test section 3 reproduces the incident: `record()` gives SET, the archive is
allowed, two more commits follow, then `verdict()` reads OPEN with a `marker:` reason,
`orientation_line()` still says "but HEAD has moved", and the guard denies.

## Decided on Sheldon's behalf

1. **Roots without this session's baseline are not judged, even though `--check` would give them a
   verdict.** With no baseline, a stale `.last_wrap` left by an earlier session reads
   `marker: skipped`, which is OPEN (test section 4 shows this). Denying on that would block a
   session for work it never did, which is exactly the cry-wolf that UNKNOWN exists to prevent.
   Such a root becomes UNKNOWN-and-allow instead. This is the one deliberate departure from "the
   same verdict as `--check`".
2. **The caller's own id spelled out counts as self**, alongside `"self"`.
3. **Beyond `project_root()`, the guard judges the payload `cwd`'s toplevel and the opted-in
   children of a non-project root**, but only where this session has a baseline. An untouched
   child reads NOT DUE, so it cannot add a false block.
4. **The UNKNOWN note goes to the user via `systemMessage`, and there is no
   `permissionDecision`.** Returning `"allow"` would skip the app's own approval prompt for
   archiving. In any case, the agent's conversation ends when it archives itself.
5. **The refusal names the sidebar as the escape hatch**, so a user who really does want to
   archive unwrapped is never trapped.
6. **A project with no `NEXT.md` gets complete silence**, matching every other hook.

Proposed README row (Known limits / hooks table, wording for the orchestrator):

> | `archive_guard.py` | PreToolUse · `archive_session` | Refuses an agent archiving its own session while the wrap verdict is `CAIRN OPEN` (including commits made after a `SET`). Allows `SET`/`NOT DUE` silently, `UNKNOWN` with one line, and fails open on any error or another session's id. **Known limit:** a hook only sees tool calls — archiving from the sidebar fires nothing and `SessionEnd` cannot block, so this closes the agent path only; the UI path stays covered by the next session's "did not finish cleanly" box. |

Proposed `docs/decisions.md` row:

> | B64 archive guard judges only roots with THIS session's baseline | Rejected: judging every root exactly as `wrap_receipt.py --check` does. Without a baseline a stale `.last_wrap` from an earlier session reads `marker: skipped` → `OPEN`, so the guard would block archives for work the session never did — the cry-wolf UNKNOWN exists to prevent. Cost: an archive from a root whose baseline stamp failed is allowed (with an UNKNOWN line) even if it is genuinely unwrapped. |

The wrap skill (not edited, another lane owns it) could say, at step 10, that `archive_guard`
refuses the self-archive while `--check` reads OPEN, so a refusal there means re-wrap rather than
retry.

## Chose not to do

- **Did not edit `wrap_receipt.py`.** `verdict()` already reads OPEN after HEAD moves past a SET
  receipt, and a test proves it. `_digest()` and all function signatures are untouched.
- **Did not use `permissionDecision: "allow"` or `"deny"` JSON.** Exit 2 plus stderr is the same
  contract as `staged_review_guard.py`, and an explicit allow would bypass the user's approval
  prompt.
- **Did not try to block the sidebar or UI archive.** It is impossible from a hook. It is
  documented as the known limit.
- **Did not judge other sessions' ids.** Their baselines are keyed to their own id, and the hook
  cannot measure them.
- **Did not touch** `CHANGELOG.md`, `BACKLOG.md`, `NEXT.md`, `README.md`, `docs/decisions.md`,
  `plugin.json`, skills, rules, `run.sh` or the install tools. I committed nothing and never
  called `archive_session` or `--record` on the real repo.
